## v0.6.3 - 2026-11-25

v0.6.3 changes no code in a package a program imports: no call or behaviour changes from v0.6.2, and no exported name is added, removed or changed, so it is a patch. What changes is go-socket's documents, its comments, its release checks and the test kit its own tests run under. A program that uses go-socket has nothing to change.

### Added
* Every pull request and every push to main runs `go vet` and `go test` on Linux, macOS and Windows in GitHub Actions, with every module fetched through the public Go module proxy, as a program that imports go-socket fetches them.

### Changed
* The README is rewritten: what go-socket does, how to install it and what each module it brings is for, a quick start that `go test` runs, its packages, and the systems each call works on. Each package's README says what the package is built on, what it adds, and what a program configures. `SECURITY.md` and `CONTRIBUTING.md` are new. Report a vulnerability privately, through GitHub's private vulnerability reporting, never in a public issue. The issue form for security problems is gone.
* Comments, lint messages and task descriptions say what each rule or check does, in place of pointing at a record elsewhere. No rule or check changes.
* The library file and the uses file, which a consumer's tooling reads to learn what each package does and which calls it replaces, move from their old folder to `.library/`: `.library/library.yaml` and `.library/uses.yaml`. Every key and every value that tooling matches on is unchanged. Their free text now names only this repository.
* go-socket's own tests run under github.com/birdtable/go-testkit v0.3.1, in place of v0.2.0. Only the tests import it, so a program that imports go-socket does not build it.

### Removed
* `api/proved.txt` and its check are gone. A release is proved instead by those GitHub Actions runs on Linux, macOS and Windows at the commit it is tagged from, with the release tier on macOS at the same commit, and these notes name the three systems. `api/contract.txt` and its check are unchanged.

Proved on macOS (arm64), Linux (amd64) and Windows (amd64): `go vet`, and `go test` with the race detector in shuffled order, ran green on each, in GitHub Actions, at the commit this tag names, with no test skipped. Four tests of the repository's own tooling, which those runs leave out until its tools resolve from the public module proxy, ran in the release tier on macOS at the same commit, with lint for every system, the API check, the tidy check and the vulnerability scan.

Nothing is added or removed: apidiff finds no change from v0.6.2 on darwin, linux or windows, and no break is declared since v0.6.2.

go.mod moves one requirement since v0.6.2: github.com/birdtable/go-testkit, from v0.2.0 to v0.3.1, imported by tests alone. The others did not move: github.com/Microsoft/go-winio v0.6.4, github.com/bored-engineer/go-launchd v0.0.0-20241220214420-b514778f4f80, github.com/coreos/go-systemd/v22 v22.7.0, github.com/docker/go-connections v0.8.2, github.com/gofrs/flock v0.13.2 and golang.org/x/sys v0.50.0. ## v0.6.2 - 2026-11-22

v0.6.2 changes no code in a package a program imports: no call or behaviour changes from v0.6.1, and no exported name is added, removed or changed, so it is a patch. What changes is go-socket's tests, its checks and its documents. A program that uses go-socket has nothing to change.

### Added
* `api/contract.txt` lists the promises a program may rely on, each with the test that holds it and the systems it is made on. It starts with `listen`'s and `peer`'s: who may reach a socket or a named pipe `Listen` makes, what `Listen` does with a name that is taken, whose account `PeerOf` names on each system, and what `Listener` refuses. `api/proved.txt` has a line for each system a release's test run proves the promises on, so a system with no line, FreeBSD among them, is untested for that release. A check holds that each promise's test exists, builds and is never skipped on the systems it names, and that a promise withdrawn after a release is declared as a break.

### Changed
* The API check is now apidiff's, in place of the generated `API.txt`, which is gone. On darwin, linux and windows it compares the code with the last release, and an incompatible change fails unless it is declared in `api/breaks/<release>.txt`. It also fails when one system has a name or a signature the others lack, so the API is the same on every system. `go doc -all` lists a release's whole API, for example `go doc -all github.com/birdtable/go-socket/listen@v0.6.2`.
* go-socket's tests start from github.com/birdtable/go-testkit, a test kit, in place of a copy of its own. go.mod requires go-testkit for the tests alone: no package's code imports it, so a program that imports go-socket does not build it.
* The hand-run release workflow takes `ref`, a commit's full sha, beside the version. With it, the Linux and Windows tiers run at that commit and nothing is published, so a fix is proven before its release. Without it, the workflow runs as before.
* The pre-push tier's race run no longer waits out the race detector's 1 s pause at exit. The release tier's run of every test keeps the pause, so a race only the pause shows still fails before a release. No test is skipped, moved or loosened, and the pre-push tier's 10 s budget is unchanged.

### Known limitations
* The release workflow's `ref` input has not yet run on GitHub's own runners, so that path is not yet proven there.
* The release tier and the pre-push tier run close to their time budgets, so a busy machine can overrun one.

Nothing is added or removed: apidiff finds no change from v0.6.1 on darwin, linux or windows, and no break is declared since v0.6.1.

## v0.6.0 - 2026-11-20

v0.6.0 changes two refusals in `listen`, one on macOS and one on Windows. No call is added, removed or changed. Read the Changed section if you pass `ReplaceEvenIfBusy` on macOS, or if your code tells `ErrHeld` from `fs.ErrPermission` on Windows.

### Changed

**listen**
* On macOS, `ReplaceEvenIfBusy` now asks whether a socket is still bound at the path before it replaces one that refuses a connection, as it does on Linux.
  * It asks with a datagram connection, which finds a bound stream socket that a stream connection can't tell from a socket a run before left.
  * A socket bound and not yet listening, and a live socket whose queue is full, which macOS refuses as it refuses a run before's, are left, and `Listen` is refused with `ErrHeld`. v0.5.0 replaced them.
  * A bind still under way when `Listen` asks may be missed on macOS.
  * The BSDs are unchanged: there the option replaces every socket that refuses.
* On Windows, `Listen` at a pipe name nobody serves, under a token that may make no pipe (an app container, or a restricted token), is refused with an error that wraps `fs.ErrPermission`. v0.5.0 returned `ErrHeld`.
  * Windows answers both that and a held name with `ERROR_ACCESS_DENIED`, so `Listen` now asks whether a pipe is at the name, connecting to nothing and taking no instance.
  * Any other answer, and a name holding a character Windows takes as a wildcard (`* ? < > "`), stays `ErrHeld`.
  * What a caller sees change is that `errors.Is(err, ErrHeld)` is false there. An `ErrHeld` error for `ERROR_ACCESS_DENIED` matches `fs.ErrPermission` too, as in v0.5.0, so test `ErrHeld` first.
  * The answer reads the name at that moment and is no proof of a missing right: a pipe another program makes and closes between the create and the look gives it too.

Nothing is added or removed: `API.txt` is the same as v0.5.0's.

## v0.5.0 - 2026-11-20

v0.5.0 adds two calls to `peer` and changes one in `listen`. A program that calls `listen.Activated()` with no names keeps working on Linux. Read the Changed section before upgrading on macOS, or if your code holds `Activated` as a value.

### Changed

**listen**
* `Activated` now takes the names of the sockets to take: `Activated(names ...string)`.
  * Code that holds `Activated` as a `func()` value no longer compiles.
  * On Linux, a call with no names takes every socket systemd passed, as before. With names, it takes those in the order named and closes the rest.
  * On macOS, it takes the sockets launchd passes, by their keys in the job's `Sockets`. A call with no names is refused with `fs.ErrInvalid`, where v0.4.0 returned `ErrNotActivated`. launchd hands a key's sockets once, so a second call for one is refused.
  * On both, a name that is empty or named twice is refused with `fs.ErrInvalid`. A name nothing was passed under is `ErrNotActivated`, and every descriptor passed is closed.
  * Each descriptor is marked close-on-exec as soon as it's taken.

### Added

**peer**
* `DialAgent(ctx, env)` dials this session's SSH agent, for `golang.org/x/crypto/ssh/agent`'s `NewClient`.
  * On macOS, Linux and the BSDs, it dials the socket `SSH_AUTH_SOCK` names, which must be an absolute path.
  * On Windows, it dials the pipe `SSH_AUTH_SOCK` names, or OpenSSH's `\\.\pipe\openssh-ssh-agent` when it's unset.
  * Windows checks the pipe's owner: `DialAgent` refuses a pipe that isn't owned by this account, SYSTEM or Administrators. Any account can create a pipe name that is free, so without this check another account could receive the session's agent requests.
  * A context with no deadline is bounded at 5 seconds. A name held and never served then answers `context.DeadlineExceeded`.
  * No agent is an error matching `fs.ErrNotExist`.
* `AgentSSHCommand()` gives the ssh command that reaches the agent `DialAgent` dials, for git's `core.sshCommand` or `GIT_SSH_COMMAND`.
  * On Windows, it's the system's own OpenSSH client, `<windows>/System32/OpenSSH/ssh.exe`, because Git for Windows' own ssh can't open an agent on a named pipe.
  * Elsewhere, it's empty, meaning git's default.

Nothing is removed: `API.txt` gains `peer.AgentSSHCommand` and `peer.DialAgent`, and changes `listen.Activated`.

## v0.4.0 - 2026-11-19

v0.4.0 adds one call to `listen` and changes nothing a program already uses. Upgrading from v0.3 needs no change.

### Added

**listen**
* `Local(folder, name)` gives the address `Listen` takes on this system for a socket the program names. That address is also what a client is told: `SSH_AUTH_SOCK`, for example.
  * On macOS, Linux and the BSDs, it's the name in the folder, made absolute. If a socket's address can't hold that path, `Local` refuses it with the error `Listen` would give, and doesn't move it to another folder.
  * On Windows, it's `\\.\pipe\<name>-<h>`, where `<h>` is 16 hex digits of the SHA-256 of the folder's absolute path. So two folders never give the same pipe, and the same folder and name always give the same one.
  * A name that is not one plain name is refused before any address is formed: empty, `.`, `..`, a slash or backslash, a NUL, or, on Windows, a name a pipe can't end in, such as one ending in a dot or a space.
  * `Local` makes nothing, and looks at the folder only to make it absolute.

Nothing is removed or moved: `API.txt` gains `listen.Local` alone.

## v0.3.0 - 2026-11-18

v0.3.0 leaves go-socket a library of sockets alone, and makes `listen` remove only a socket it can show is its own, and give its mode only to its own. A program upgrading from v0.2 has these eight changes to make:

- `registry` and `wire` are gone, with no alias. Keep your own table of kinds, and serve `net/http` on the listener `listen.Listen` returns.
- `caller.Front`, `caller.Visitor`, `caller.FoldLogin` and `caller.SameLogin` are gone. Each was a program's own rule; keep your own.
- On Windows, `listen.Listen` serves a named pipe you name, `\\.\pipe\<name>`, in place of a Unix socket: give it that name, and dial it with `peer.DialPipe`. `peer.ListenSocket` is gone on every system: to let accounts in by SID, use `peer.ListenPipe`.
- On macOS, Linux and the BSDs, `listen.Listen` no longer replaces a socket left at the path unless you give `ReplaceEvenIfBusy`. Without it, such a socket is refused with `ErrMaybeBusy` and left.
- On macOS, Linux and the BSDs, a connection `listen`'s `Accept` returns is no longer a `*net.UnixConn`, and the socket's folder must take hard links. A type assertion to `*net.UnixConn` on an accepted connection fails; use the `net.Conn` methods, or `SyscallConn`, which it still has. A socket in a folder on FAT, exFAT or a share that takes no hard links now fails to listen: put it on a filesystem that takes them. So does a program whose AppArmor profile or SELinux policy lets it make only the socket and its lock file there: let it also make a folder there, link and remove names in it, and remove it.
- On macOS, Linux and the BSDs, `listen.SocketMode` must let the socket's owner write (0200), or `Listen` refuses it. Give 0600, or 0660 with `SocketGroup`.
- `caller.LoginProxy.RemoteUser` refuses a user or group with a space other than a space or tab at either end, where v0.2.0 took it off. Have your proxy write them without it.
- On macOS, Linux and the BSDs, a name another program put at the path since `listen.Listen` looked is refused with an error that wraps `ErrMaybeBusy` and `fs.ErrExist`, no longer `syscall.EADDRINUSE`. Check for `ErrMaybeBusy` in place of `syscall.EADDRINUSE`.

Each one is below, under Removed and Breaking, by package.

### Removed

**registry**
* The whole package: `New`, `Of` and its methods `Register`, `Open`, `Forget`, `Kinds` and `Here`, `Away`, `NotOnThisMachine` with its fields `Kind` and `Noun` and its methods `Error` and `Is`, `ErrNotHere` and `ErrUnknownKind`. It had nothing to do with sockets. A program that opens an implementation by its kind keeps its own table: a map from the kind to its open function, and an error of its own for a kind not on this machine.

**wire**
* The whole package: `WriteFrame`, `ReadFrame`, `ReadRaw`, `Parse`, `Decode`, `Envelope` with its fields `ID`, `Type`, `Body` and `Error`, `Error` with its fields `Kind`, `Msg` and `Hint` and its method `Error`, `ErrorOf`, `ErrOversized` with its fields `N` and `Max` and its method `Error`, `ErrNotAMessage`, `MaxMessage`, `KindRefused`, `KindBusy`, `KindFailed`, `Refused`, `Busy` and `Failed`. A program that spoke wire serves `net/http` on the listener `listen.Listen` returns. It caps each body itself with `http.MaxBytesReader`, and reads and writes its messages as JSON bodies, for a strict read with `encoding/json/v2` and `json.RejectUnknownMembers(true)`.

**caller**
* `Front`, with its fields `Who`, `May` and `Prefix` and its methods `Write` and `Read`, and `Visitor`, with its fields `Who` and `May`. A front of your own, one header for who is asking and one for what they may do, is your program's layout, so keep it in your program. If your front is a login proxy, read it with `LoginProxy`, giving the header names and separator your proxy writes.
* `FoldLogin` and `SameLogin`. When two logins are one person is your program's rule. `SameLogin(a, b)` was: `a` and `b` are equal once their ASCII capitals are made small, and nothing else is changed.

**peer**
* `ListenSocket`, on every system, with the Unix socket it made on Windows. To let accounts in by SID, use `peer.ListenPipe(name, sids...)` and dial with `peer.DialPipe`. For your account and SYSTEM alone, give `listen.Listen` the name `\\.\pipe\<name>`.

Nothing moved: every name above is gone, with no alias.

### Breaking

**listen**
* On Windows, `Listen` serves a named pipe, and you name it: `\\.\pipe\` and then a name, with no default. A path there, or a pipe's name on any other system, is refused with the new `ErrPipeName`. The pipe is owned by your account, and only your account and SYSTEM may open it, set as it is made. Clients on other machines are refused. A pipe already at the name, made by anyone, is `ErrHeld`. While your program's own ends of the pipe are open, the listener and each connection it accepted (which holds the name past the listener's `Close`), a `Listen` at the name is `ErrHeld`. Don't count on a client that keeps its end open to hold the name: on Windows 11 (build 26200) a restart's `Listen` took the name once the program's ends were closed, and that client's end reached nothing of the new pipe. A Windows that kept the name would answer that `Listen` with `ErrHeld` until the client closed. There is no lock file and no stale socket on Windows. `SocketMode`, `SocketGroup` and `ReplaceEvenIfBusy` are refused there with an error that wraps `errors.ErrUnsupported` (v0.2.0 refused `SocketMode`, whatever the mode, and `SocketGroup` there too; only `ReplaceEvenIfBusy`'s refusal is new). To upgrade a Windows program: give `Listen` `\\.\pipe\<name>` in place of a path, drop those three options, and dial with `peer.DialPipe` or go-winio's `DialPipe`. `peer.Listener` lets connections in by SID as it does on `peer.ListenPipe`.
* On macOS, Linux and the BSDs, `Listen` no longer replaces a socket at the path that refuses a connection (Windows has no socket there, above). A busy program that takes no lock refuses one the same way, and v0.2.0 could remove that program's live socket. Now `Listen` refuses it with the new `ErrMaybeBusy` and leaves it. A socket a crashed run left behind, which v0.2.0 replaced on its own, now needs the new option `ReplaceEvenIfBusy`. Give it only if your program alone listens at its path. On Linux, with the option, `Listen` first checks whether a socket is still bound to the file, and refuses one that is bound and not yet listening with `ErrHeld`.
* On Unix, `Listen` refuses a `SocketMode` that doesn't let its owner write (0200), with an error that wraps `fs.ErrInvalid`, before it makes anything: it dials its own socket to prove its path, and a connect needs write. Give a mode with 0200: 0600, or 0660 with `SocketGroup`.
* On Unix, a connection `Accept` returns is not a `*net.UnixConn`, though it has all of one's methods, `SyscallConn` among them, so a type assertion to `*net.UnixConn` fails. Use the `net.Conn` methods, or `SyscallConn`. Its `LocalAddr` is the path, and so is the listener's `Addr`.
* On Unix, a name another program put at the path since `Listen` looked is refused by the hard link (see Security), with an error that wraps `ErrMaybeBusy` and `fs.ErrExist`. It was the bind's `EADDRINUSE`, so a check for `syscall.EADDRINUSE` no longer matches: check `errors.Is(err, listen.ErrMaybeBusy)`.
* On Unix, the socket's folder must take hard links, so `Listen` fails on FAT, exFAT and some network shares. Put the socket on a filesystem that takes them.
* On Unix, `Listen` must be allowed to make a folder in the socket's folder, link and remove names in it, and remove it. A program whose AppArmor profile or SELinux policy grants only the socket and its lock file there now fails to listen, and nothing is left at the path. Grant those too.

**caller**
* `LoginProxy.RemoteUser` now trims only spaces and tabs from the user and each group, as HTTP trims a header value, where it trimmed every Unicode space. A user or group that still starts or ends with another space, a no-break space say, is now an error, where v0.2.0 read it with the space taken off. A vertical tab, form feed or line break at either end is an error too. Have your proxy write the user and groups without them.

### Changed

**listen**
* `Close` removes the socket only while `<path>.lock` is still the lock it holds and the path is still its socket. Otherwise it leaves the path and returns an error that wraps the new `ErrSocketLeft`.
* On every system, `Listen` refuses a group that isn't there before it makes anything.
* On Unix, the socket is bound in a private folder beside the path and hard linked to it (see Security). Besides the changes under Breaking, these things follow:
  * The socket's own address is still its private name, which is gone once the socket is at the path. A client's `RemoteAddr` and `getpeername(2)`, `ss -xl` and `/proc/net/unix` show that name, not the path.
  * A path is refused before anything is made if its private name doesn't fit a Unix socket's address. That name is the folder plus 10 bytes, so a short name in a folder whose own path is near that limit, which fit before, is now refused.
  * A private folder that can't be removed once the socket is at its path does not fail `Listen`. On an NFS client, for one, the private name stays in it as a `.nfsXXXX` name while the socket is open. `Close` removes the folder once the socket is closed, or says why it could not.
  * A process killed while `Listen` starts may leave a private folder beside the path, a `.` and six hex digits, and no later start removes it.

### Security

* **listen:** `Listen` no longer removes a live socket that another program bound at the path between `Listen`'s look and its bind. v0.2.0 bound through go-connections, which unlinks whatever is at the path first, so a program that takes no lock and listened there in that gap lost its socket, on every system. `Listen` now binds itself, and removes only a socket `ReplaceEvenIfBusy` lets it replace. On Unix it then proves the socket at the path is its own: it looks at the path, dials it with a fresh nonce, accepts that dial on its own socket, and looks again. A path another program unlinked or bound since is left, and `Listen` fails with `ErrMaybeBusy`, where v0.2.0's `Close` would have removed that program's socket. A client connection made before the proof is handed, unread, to the first `Accept`. When the proof's dial fails, a ctx that ended among the ways, `Listen` removes the path while it is still its own socket's file, so a `Listen` that fails for its own reason leaves no socket at the path. It fails with the dial's own error, which wraps the ctx's, and not with `ErrMaybeBusy`; another program's socket there is left, and that failure wraps `ErrMaybeBusy`. A failure before the socket is at its path removes nothing there. One gap remains, in the two removals without `ReplaceEvenIfBusy`: `Close` and a failed proof each look at the path and then remove it, and a program that takes no lock and swaps the path in the instant between the two still loses its socket. `Listen`'s doc names it.
* **listen:** On macOS, Linux and the BSDs, `Listen` no longer gives its socket's mode and group to another program's socket. v0.2.0 set them by path once bound, so a program that takes no lock, and unlinked and bound at the path in that instant, had its socket given them. With `SocketMode(0o666)` or `SocketGroup`, that opened its socket to others. `Listen` now binds in a private folder beside the path, made 0700, and gives the socket its mode and group there. It listens, and only then puts the socket at the path with a hard link, which refuses a name already there and leaves it. The private name and folder are removed on every way out, or by `Close` where the folder can't be removed while the socket is open.

## v0.2.0 - 2026-11-18

v0.2.0 takes out what was a program's own choice, so a program upgrading from v0.1 has these changes to make:

- `listen.Listen` takes a `context.Context` with a deadline, and `listen.Options` has no default waits.
- `caller`'s login-proxy and Tailscale-version helpers are now values the program names.
- On Windows, `listen.Listen` refuses a socket path through a junction or link among its folders, or on a share or a subst or mapped drive letter.

Each one is below, by package.

### Removed

**caller**
* `MinMajor`, `MinMinor` and `CheckVersion`. The oldest Tailscale a program supports is its own: read the version with `ParseVersion` and compare it with your floor. Below Tailscale 1.92, `tailscale serve` lets a caller write its own grants.
* `TailscaledSocket`. Where tailscaled's socket lives belongs to the system that runs it, so pass its path to `TailscaledUID` yourself.
* `Serve`, `Serve.Args` and `Serve.Line`. The `tailscale serve` command line is the program's own.
* `IsName`, `IsSegment`, `CheckPattern` and `Expand`. How a program names its permissions, and how a pattern grants them, are its own.
* `Roles`. Read `Served.Values` into a type of your own.
* `HeaderRemoteUser`, `HeaderRemoteGroups`, and the functions `RemoteUser` and `RemoteHeaders`. They are now methods of `LoginProxy`, below.

### Changed

**listen**
* `Listen` takes a `context.Context`, and refuses one with no deadline. The deadline bounds the TCP listen and the check for a live socket at the path, which was fixed at one second.
* `Options.ReadHeaderTimeout` (was 10 s), `Options.KeepAlive` (was 2 min) and `Grace` (was 5 s) have no defaults, and `NewIdle` takes `linger`, how long connections still open at the end get (was 1 s). `Serve` refuses any of them at zero or below, by name, before it serves. The socket's 0600 mode stays the default.
* On Windows, `Listen` refuses `SocketMode` with an error wrapping `errors.ErrUnsupported`, as it refuses `SocketGroup`. A Windows socket has an access list, not a mode.
* On Windows, `Listen` proves the name is the socket it bound before it returns (see Security, below), and `ctx`'s deadline bounds that proof too. So it refuses a path whose final path is not the path as written: one through a junction or link among its folders, or on a share or a subst or mapped drive letter. `Close` removes the socket through the handle held since the proof, not by path.

**caller**
* `LoginProxy` names the headers your login proxy writes: `LoginProxy{User, Groups, Separator}`, or `LoginProxy{User, NoGroups: true}` for a proxy that writes no groups header. Its `RemoteUser(h, fromProxy)` reads them, with every check the old function made. It also refuses a header name that is empty or not an HTTP token, a name given twice, a missing or contradictory groups setting, and a separator that is not `|` or an ASCII mark outside an HTTP token. Its `RemoteHeaders()` lists only the headers it reads, the user's and the groups'. v0.1's `RemoteHeaders()` also listed `Remote-Email`, `Remote-Name` and `Remote-Sub`, so a program that reads any of those three must now delete them itself from every request not from its proxy. A program that read `Remote-User` and `Remote-Groups` writes `LoginProxy{User: "Remote-User", Groups: "Remote-Groups", Separator: ','}.RemoteUser(h, fromProxy)`.
* `TailscaleServe(h, capability, limit)` takes the cap on the grants header, in bytes. 0 keeps the old cap of 64 KiB (`MaxCaps`), and 1 to 1,048,576 (net/http's 1 MiB) is the cap itself. A cap below 0 or over 1 MiB is refused before any header is read, and `ErrTooLong` reports the length and the cap. `TailscaleServe(h, capability)` becomes `TailscaleServe(h, capability, 0)`.

### Added

**caller**
* `ParseVersion` reads a Tailscale version's major and minor from its short or long form. Anything but decimal digits in either is no version.

**peer**
* `ListenSocket` on Windows makes a Unix socket that only this account, Administrators, SYSTEM and the SIDs you pass may open. Each SID gets only the rights a dial needs, and nothing is inherited. The SIDs are checked as `ListenPipe` checks them, before anything is made, and `ListenSocket` also refuses the wide groups a pipe takes, a domain's Domain Users among them. `ListenSocket(ctx, path, sids...)` takes a `context.Context` and refuses one with no deadline, before anything is made; the deadline bounds the proof that the name is the socket it bound (see Security, below). It replaces nothing at the path, and a refused start leaves the socket there, for the program to remove before the next start. Off Windows it returns `errors.ErrUnsupported`.

### Security

* **wire:** `ReadRaw`, and so `ReadFrame`, reads a frame's body in steps. A reader holds at most twice the bytes that arrived, or 64 KiB, never the length the other end announced. Before, a peer that sent a maximum length and nothing more made the reader hold the whole cap, per connection.
* **listen, peer (Windows):** `listen.Listen` and `peer.ListenSocket` prove the name is the socket they bound before they return, since Windows says nothing of which file a bind made. The name is opened as itself, with no link or junction at it followed, and held with no share for delete, so it can be neither renamed nor removed until `Close`, which removes it through that handle. Its final path must be the name, so no folder of it is a junction or link. It must be a socket owned by the owner of what this process makes, and the access list is set on that handle. Then the name is dialed, and the listener writes each connection it accepts a fresh random nonce: the name is the listener's only when the dial reads back one of them. Connections accepted before the dial's are closed unread. A name swapped since the bind is refused; past 16 early connections, or past `ctx`'s deadline, the call fails. Either way the socket is closed and the name left. Before, `listen` set the list by path, through go-connections, and a socket another account bound at the name between the bind and the look was taken for this one. Both packages make these Windows calls through one internal package they share.
* **The module:** no file, of any system and tests included, uses `//go:linkname`. go-socket's lint now reads every system the module builds for, eleven, and its tests refuse any source the lint can't read, such as assembly, cgo or a symbolic link. Unused bans on other libraries were lifted. None of this changes what a program that imports go-socket may use.
