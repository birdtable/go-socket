## v0.2.0 - 2026-11-18

v0.2.0 takes out what was a program's own choice, so a program upgrading from v0.1 has these changes to make:

- `listen.Listen` takes a `context.Context` with a deadline, and `listen.Options` has no default waits.
- `caller`'s login-proxy and Tailscale-version helpers are now values the program names.
- On Windows, `listen.Listen` refuses a socket path through a junction or link among its folders, or on a share or a subst or mapped drive letter.

Each one is below, by package.

### Removed

**caller**
* `MinMajor`, `MinMinor` and `CheckVersion`. The oldest Tailscale a program supports is its own: read the version with `ParseVersion` and compare it with your floor. Below Tailscale 1.92, `tailscale serve` lets a caller write its own grants.
* `TailscaledSocket`. Where tailscaled's socket lives belongs to the system that runs it, so pass its path to `TailscaledUID` yourself.
* `Serve`, `Serve.Args` and `Serve.Line`. The `tailscale serve` command line is the program's own.
* `IsName`, `IsSegment`, `CheckPattern` and `Expand`. How a program names its permissions, and how a pattern grants them, are its own.
* `Roles`. Read `Served.Values` into a type of your own.
* `HeaderRemoteUser`, `HeaderRemoteGroups`, and the functions `RemoteUser` and `RemoteHeaders`. They are now methods of `LoginProxy`, below.

### Changed

**listen**
* `Listen` takes a `context.Context`, and refuses one with no deadline. The deadline bounds the TCP listen and the check for a live socket at the path, which was fixed at one second.
* `Options.ReadHeaderTimeout` (was 10 s), `Options.KeepAlive` (was 2 min) and `Grace` (was 5 s) have no defaults, and `NewIdle` takes `linger`, how long connections still open at the end get (was 1 s). `Serve` refuses any of them at zero or below, by name, before it serves. The socket's 0600 mode stays the default.
* On Windows, `Listen` refuses `SocketMode` with an error wrapping `errors.ErrUnsupported`, as it refuses `SocketGroup`. A Windows socket has an access list, not a mode.
* On Windows, `Listen` proves the name is the socket it bound before it returns (see Security, below), and `ctx`'s deadline bounds that proof too. So it refuses a path whose final path is not the path as written: one through a junction or link among its folders, or on a share or a subst or mapped drive letter. `Close` removes the socket through the handle held since the proof, not by path.

**caller**
* `LoginProxy` names the headers your login proxy writes: `LoginProxy{User, Groups, Separator}`, or `LoginProxy{User, NoGroups: true}` for a proxy that writes no groups header. Its `RemoteUser(h, fromProxy)` reads them, with every check the old function made. It also refuses a header name that is empty or not an HTTP token, a name given twice, a missing or contradictory groups setting, and a separator that is not `|` or an ASCII mark outside an HTTP token. Its `RemoteHeaders()` lists only the headers it reads, the user's and the groups'. v0.1's `RemoteHeaders()` also listed `Remote-Email`, `Remote-Name` and `Remote-Sub`, so a program that reads any of those three must now delete them itself from every request not from its proxy. A program that read `Remote-User` and `Remote-Groups` writes `LoginProxy{User: "Remote-User", Groups: "Remote-Groups", Separator: ','}.RemoteUser(h, fromProxy)`.
* `TailscaleServe(h, capability, limit)` takes the cap on the grants header, in bytes. 0 keeps the old cap of 64 KiB (`MaxCaps`), and 1 to 1,048,576 (net/http's 1 MiB) is the cap itself. A cap below 0 or over 1 MiB is refused before any header is read, and `ErrTooLong` reports the length and the cap. `TailscaleServe(h, capability)` becomes `TailscaleServe(h, capability, 0)`.

### Added

**caller**
* `ParseVersion` reads a Tailscale version's major and minor from its short or long form. Anything but decimal digits in either is no version.

**peer**
* `ListenSocket` on Windows makes a Unix socket that only this account, Administrators, SYSTEM and the SIDs you pass may open. Each SID gets only the rights a dial needs, and nothing is inherited. The SIDs are checked as `ListenPipe` checks them, before anything is made, and `ListenSocket` also refuses the wide groups a pipe takes, a domain's Domain Users among them. `ListenSocket(ctx, path, sids...)` takes a `context.Context` and refuses one with no deadline, before anything is made; the deadline bounds the proof that the name is the socket it bound (see Security, below). It replaces nothing at the path, and a refused start leaves the socket there, for the program to remove before the next start. Off Windows it returns `errors.ErrUnsupported`.

### Security

* **wire:** `ReadRaw`, and so `ReadFrame`, reads a frame's body in steps. A reader holds at most twice the bytes that arrived, or 64 KiB, never the length the other end announced. Before, a peer that sent a maximum length and nothing more made the reader hold the whole cap, per connection.
* **listen, peer (Windows):** `listen.Listen` and `peer.ListenSocket` prove the name is the socket they bound before they return, since Windows says nothing of which file a bind made. The name is opened as itself, with no link or junction at it followed, and held with no share for delete, so it can be neither renamed nor removed until `Close`, which removes it through that handle. Its final path must be the name, so no folder of it is a junction or link. It must be a socket owned by the owner of what this process makes, and the access list is set on that handle. Then the name is dialed, and the listener writes each connection it accepts a fresh random nonce: the name is the listener's only when the dial reads back one of them. Connections accepted before the dial's are closed unread. A name swapped since the bind is refused; past 16 early connections, or past `ctx`'s deadline, the call fails. Either way the socket is closed and the name left. Before, `listen` set the list by path, through go-connections, and a socket another account bound at the name between the bind and the look was taken for this one. Both packages make these Windows calls through one internal package they share.
* **The module:** no file, of any system and tests included, uses `//go:linkname`. go-socket's lint now reads every system the module builds for, eleven, and its tests refuse any source the lint can't read, such as assembly, cgo or a symbolic link. Unused bans on other libraries were lifted. None of this changes what a program that imports go-socket may use.
