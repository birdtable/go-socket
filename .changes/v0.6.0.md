## v0.6.0 - 2026-11-20

v0.6.0 changes two refusals in `listen`, one on macOS and one on Windows. No call is added, removed or changed. Read the Changed section if you pass `ReplaceEvenIfBusy` on macOS, or if your code tells `ErrHeld` from `fs.ErrPermission` on Windows.

### Changed

**listen**
* On macOS, `ReplaceEvenIfBusy` now asks whether a socket is still bound at the path before it replaces one that refuses a connection, as it does on Linux.
  * It asks with a datagram connection, which finds a bound stream socket that a stream connection can't tell from a socket a run before left.
  * A socket bound and not yet listening, and a live socket whose queue is full, which macOS refuses as it refuses a run before's, are left, and `Listen` is refused with `ErrHeld`. v0.5.0 replaced them.
  * A bind still under way when `Listen` asks may be missed on macOS.
  * The BSDs are unchanged: there the option replaces every socket that refuses.
* On Windows, `Listen` at a pipe name nobody serves, under a token that may make no pipe (an app container, or a restricted token), is refused with an error that wraps `fs.ErrPermission`. v0.5.0 returned `ErrHeld`.
  * Windows answers both that and a held name with `ERROR_ACCESS_DENIED`, so `Listen` now asks whether a pipe is at the name, connecting to nothing and taking no instance.
  * Any other answer, and a name holding a character Windows takes as a wildcard (`* ? < > "`), stays `ErrHeld`.
  * What a caller sees change is that `errors.Is(err, ErrHeld)` is false there. An `ErrHeld` error for `ERROR_ACCESS_DENIED` matches `fs.ErrPermission` too, as in v0.5.0, so test `ErrHeld` first.
  * The answer reads the name at that moment and is no proof of a missing right: a pipe another program makes and closes between the create and the look gives it too.

Nothing is added or removed: `API.txt` is the same as v0.5.0's.
