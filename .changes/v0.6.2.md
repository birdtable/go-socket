## v0.6.2 - 2026-11-22

v0.6.2 changes no code in a package a program imports: no call or behaviour changes from v0.6.1, and no exported name is added, removed or changed, so it is a patch. What changes is go-socket's tests, its checks and its documents. A program that uses go-socket has nothing to change.

### Added
* `api/contract.txt` lists the promises a program may rely on, each with the test that holds it and the systems it is made on. It starts with `listen`'s and `peer`'s: who may reach a socket or a named pipe `Listen` makes, what `Listen` does with a name that is taken, whose account `PeerOf` names on each system, and what `Listener` refuses. `api/proved.txt` has a line for each system a release's test run proves the promises on, so a system with no line, FreeBSD among them, is untested for that release. A check holds that each promise's test exists, builds and is never skipped on the systems it names, and that a promise withdrawn after a release is declared as a break.

### Changed
* The API check is now apidiff's, in place of the generated `API.txt`, which is gone. On darwin, linux and windows it compares the code with the last release, and an incompatible change fails unless it is declared in `api/breaks/<release>.txt`. It also fails when one system has a name or a signature the others lack, so the API is the same on every system. `go doc -all` lists a release's whole API, for example `go doc -all github.com/birdtable/go-socket/listen@v0.6.2`.
* go-socket's tests start from github.com/birdtable/go-testkit, a test kit, in place of a copy of its own. go.mod requires go-testkit for the tests alone: no package's code imports it, so a program that imports go-socket does not build it.
* The hand-run release workflow takes `ref`, a commit's full sha, beside the version. With it, the Linux and Windows tiers run at that commit and nothing is published, so a fix is proven before its release. Without it, the workflow runs as before.
* The pre-push tier's race run no longer waits out the race detector's 1 s pause at exit. The release tier's run of every test keeps the pause, so a race only the pause shows still fails before a release. No test is skipped, moved or loosened, and the pre-push tier's 10 s budget is unchanged.

### Known limitations
* The release workflow's `ref` input has not yet run on GitHub's own runners, so that path is not yet proven there.
* The release tier and the pre-push tier run close to their time budgets, so a busy machine can overrun one.

Nothing is added or removed: apidiff finds no change from v0.6.1 on darwin, linux or windows, and no break is declared since v0.6.1.
