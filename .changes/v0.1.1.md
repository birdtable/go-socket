## v0.1.1 - 2026-11-17
### Changed
* The release workflow runs by hand alone, with the tag as its input, on Linux and Windows, and no longer starts on a pushed tag; it creates the release only when both tiers are green on the tag's tree.
* A tier's members run together, each command held to a timeout, so a member that hangs fails by its name; a member that reads only the tree skips when its inputs are what they were at its last pass, and runs again when its stamp is missing, as a killed run leaves it; release skips nothing, and VERSION reaches gorelease and changie as a variable, never as shell text.
### Security
* go-socket's own lint bans what the modules it wraps would let a file do by hand: no umask, raw system call of the Syscall family, hand flock, LockFileEx or environment read past os (syscall, x/sys unix or windows) in any file, peer's system files included, and no raw system call through a DLL's proc (Call on a Proc or LazyProc), no DLL loaded and no proc taken from one (NewLazyDLL, NewLazySystemDLL, LoadDLL, LoadLibrary, NewProc, FindProc, GetProcAddress and kin), no DLL or proc type named and no field of one read or written, in any file but the two x/sys does not wrap, peer's ImpersonateNamedPipeClient and its test's CreateRestrictedToken, each acquisition and each call excepted by its own source line, and either proc used on its own call line alone.

The non-test Go lines outside internal/: 2721.

go-socket v0.1.1 requires github.com/Microsoft/go-winio v0.6.4, github.com/coreos/go-systemd/v22 v22.7.0, github.com/docker/go-connections v0.8.2, github.com/gofrs/flock v0.13.2 and golang.org/x/sys v0.50.0, as v0.1.0 does. A project that takes a module only once it is 14 days old can take it from 22 November 2026.
